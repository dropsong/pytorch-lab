
> 加权求和不是得到一个数吗，而不是一个向量？

你的这个疑问非常经典！你之所以认为“加权求和得到的是一个数”，是因为你在直觉上把“一维数字（标量）的求和”和“多维向量的求和”混淆了。
一句话直接回答：在 Attention 中，我们是对多个“向量”进行加权求和，所以结果依然是一个“向量”，而不是一个数。
为了让你完全明白，我们用一个极其简单的例子来拆解。

## 1. 为什么你觉得是一个数？（标量的加权求和）

如果你手里有 3 个普通的数字（标量）：

* 考试成绩：数学 = 90，英语 = 80，语文 = 85
* 权重（占比）：数学 = 0.5，英语 = 0.3，语文 = 0.2
* 加权求和：$90 \times 0.5 + 80 \times 0.3 + 85 \times 0.2 = 45 + 24 + 17 = 86$

因为相加的每一个项都是一个数字，所以最后加出来的必然是一个数字。这也是你提到的“点积（Dot Product）”通常产生的结果。

## 2. 为什么 Attention 得到的是向量？（向量的加权求和）

在 Seq2Seq 模型中，编码器的输出（Encoder Outputs）不是普通的数字，而是一排向量。每个向量代表一个词的语义（假设维度是 4 维）。
假设输入序列有 3 个词，它们的向量（EO）分别是：

* 词 1 的向量：$[1, 0, 1, 2]$
* 词 2 的向量：$[0, 2, 2, 0]$
* 词 3 的向量：$[3, 1, 0, 1]$

此时，Attention 算出了 3 个权重（Softmax 之后的结果，和为1）：

* 权重 = $[0.5, 0.3, 0.2]$

现在，我们严格按照原文的步骤执行“加权求和”：

* 第一步：加权（权重乘以对应的向量）
* 0.5 $\times$ 词1向量 = $0.5 \times [1, 0, 1, 2] = [0.5, 0.0, 0.5, 1.0]$
   * 0.3 $\times$ 词2向量 = $0.3 \times [0, 2, 2, 0] = [0.0, 0.6, 0.6, 0.0]$
   * 0.2 $\times$ 词3向量 = $0.2 \times [3, 1, 0, 1] = [0.6, 0.2, 0.0, 0.2]$
* 第二步：求和（把上面三个新向量加在一起）
我们将它们对应位置的数字相加：
$$\begin{aligned} \text{Context Vector} &= [0.5, 0.0, 0.5, 1.0] \\ &+ [0.0, 0.6, 0.6, 0.0] \\ &+ [0.6, 0.2, 0.0, 0.2] \\ &= [1.1, 0.8, 1.1, 1.2] \end{aligned}$$ 

## 总结
看，最终得到的 [1.1, 0.8, 1.1, 1.2] 依然是一个 4 维的向量！
原文描述的 sum(attention_weights * EO, axis = 1) 做的正是这件事情：

   1. attention_weights * EO 实现了第一步（加权）。
   2. sum(..., axis = 1) 沿着序列长度方向把这几个向量加在了一起，实现了第二步（求和）。

因为相加的每一个单元都是向量，所以它们揉合（求和）在一起之后，依然是一个特定维度的向量，这就是上下文向量（Context Vector）。
